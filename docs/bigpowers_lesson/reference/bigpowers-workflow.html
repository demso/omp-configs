Bigpowers: карманная карта

Не список магических команд, а набор узких процедур, которые превращают намерение в проверяемое изменение.

Ментальная модель

Skill

Инструкция для одного вида работы: исследовать, ограничить scope, спланировать, проверить или отревьюить. Это не «агент с характером» и не команда, которую нужно применять всегда.

Specs

Операционная память проекта. Решения, план, состояние и доказательства лежат в specs/, поэтому следующий агент не должен восстанавливать их из чата.

Gate

Условие, которое запрещает двигаться дальше без наблюдаемого факта: scope ограничен, baseline зелёный, UAT пройден, аудит не нашёл проблем.

Evidence

Сохранённый результат запускаемой проверки или UAT. «Код выглядит верно» — не evidence.

Три правила против процессного карго-культа

  1. Начинайте с состояния, а не с любимого skill. Для существующей работы это обычно survey-context.
  2. Запускайте skill только когда его входы существуют. Например, slice-tasks после scope, plan-work после slices.
  3. Оптимизируйте доказательства, а не количество артефактов. Лёгкий P3 change не должен получать P0-церемонию, но ни один рискованный change не должен завершаться без UAT/evidence.

Основные источники: локальные инструкции using-bigpowers, orchestrate-project, verify-work.
