Как работать с docs-mcp-server

 ### Идея

 Это локальный индекс чужой документации. Цикл простой: один раз проиндексировал → потом ищешь мгновенно и офлайн, без парсинга сайтов на каждый запрос. Я (агент) хожу в него через MCP-инструменты вместо
 веб-поиска, когда дока уже в индексе.

 ### Три способа взаимодействия

 ┌──────────────────────────────┬────────────────────────────────────────────────────────────────────┐
 │ Способ                       │ Когда                                                              │
 ├──────────────────────────────┼────────────────────────────────────────────────────────────────────┤
 │ Через меня в сессии          │ Основной. Говорите человеческим языком — я вызываю MCP-инструменты │
 ├──────────────────────────────┼────────────────────────────────────────────────────────────────────┤
 │ Web UI http://127.0.0.1:6280 │ Визуально посмотреть библиотеки, статус джобов, запустить scrape   │
 ├──────────────────────────────┼────────────────────────────────────────────────────────────────────┤
 │ CLI docs-mcp-server <cmd>    │ Скрипты, разовые действия из терминала                             │
 └──────────────────────────────┴────────────────────────────────────────────────────────────────────┘

 ### Типичные сценарии (что говорить мне)

 1. Проиндексировать документацию:

 │ «проиндексируй доки react с react.dev»

 Я вызову scrape_docs с URL. Источники: сайты, GitHub-репо, npm, PyPI, локальные файлы. Индексация идёт фоновой джобой — большие сайты минуты. Из терминала то же самое:

 ```bash
docs-mcp-server scrape react https://react.dev/reference/react
 ```

 2. Искать по индексу:

 │ «найди в доках react про useEffect cleanup»

 Я вызову search_docs — получу релевантные куски с цитатами, а не весь сайт. Если настроить embeddings (OPENAI_API_KEY), поиск станет семантическим; сейчас — полнотекстовый.

 3. Прочитать одну страницу без индексации:

 │ «скачай страницу https://… в markdown»

 fetch_url — разовый fetch, в индекс не пишется.

 4. Управление:

 │ «что у нас проиндексировано?» / «обнови доки X» / «удали старую версию»

 list_libraries, refresh_version (пере-scrape только изменившихся страниц), remove_docs.

 ### Роль скилов

 Три установленных скила — это моя «инструкция по применению»: docs-search учит правильно строить запросы и резолвить версии, docs-manage — управлять индексом, fetch-url — когда брать страницу напрямую. Вам
 ничего с ними делать не надо — они срабатывают автоматически, когда задача подходит под описание.

 ### Практические замечания

 - Версионирование: одна библиотека может иметь несколько версий в индексе (react latest, react 18) — при scrape указывается версия, при поиске я могу её сузить.
 - Перезаписи нет: scrape той же версии отклоняется — либо replace: true, либо refresh_version.
 - Данные: индекс живёт в ~/.local/share/docs-mcp-server (SQLite), переживает рестарт сервера. Сам сервер — нет: после перезагрузки WSL поднимать docs-mcp-server заново (или systemd unit из инструкции).
 - Из Windows: Web UI по http://<WSL-IP>:6280 (нужен запуск с --host 0.0.0.0).
